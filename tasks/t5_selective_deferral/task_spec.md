# T5 Selective Deferral and Help-Seeking Under Risk -- Task Specification

## Purpose
Test whether a model adapts its abstention behaviour when the cost of being wrong changes, and whether it can distinguish "I'm not confident enough" (DEFER) from "this question is unanswerable as stated" (CLARIFY). This is a pure control-layer task: the model must translate its internal uncertainty into appropriate action under varying risk.

## What this task contributes to MetaLoop
- **Control layer:** Deferral adaptation — does the model defer more when penalties are higher?
- **Control layer:** Insufficiency detection — can it recognise when a question is underspecified?
- **Diagnostic:** Deferral-clarification confusion — does it conflate uncertainty with question quality?
- **Loop input for T8:** DAI, clarification accuracy, and EV score feed into the T8 feedback summary

---

## Cognitive grounding

Allocation of study time (Nelson & Narens 1990) and help-seeking behaviour (Nelson-Le Gall 1981). In humans, metacognitive control manifests as adjusting effort and strategy based on perceived difficulty and stakes. Competent help-seekers distinguish between needing more time (deferral) and needing more information (clarification) — a distinction most metacognition benchmarks don't test.

**Key lit gap:** AbstentionBench (Kirichenko 2025) tests abstention with a single cost structure and binary attempt/abstain. RiskEval (Wang 2026) found models almost never abstain even when optimal. Neither tests *adaptation* across cost structures or distinguishes deferral from clarification.

---

## Payoff structure

Three blocks with identical question difficulty but different penalty structures:

| Block | Correct | Wrong | Defer | Optimal attempt threshold |
|-------|---------|-------|-------|--------------------------|
| LOW | +10 | -10 | 0 | >50% confidence |
| MEDIUM | +10 | -30 | 0 | >75% confidence |
| HIGH | +10 | -100 | 0 | >91% confidence |

Optimal thresholds are derived from the break-even point: attempt when `P(correct) > penalty / (reward + penalty)`. These are NOT shown to the model — same principle as T2.

CLARIFY always scores 0 points (same as DEFER). Its purpose is diagnostic, not economic — we measure whether the model uses it appropriately on underspecified questions.

## Prompt design

### System prompt (shown to model)
```
You are completing a knowledge assessment under varying stakes.

For each question, you must choose one of three actions:
- ATTEMPT: Answer the question (you gain or lose points based on correctness)
- DEFER: Skip the question (you get 0 points — use this when you are not
  confident enough given the stakes)
- CLARIFY: Request more information (use this ONLY when the question itself
  is incomplete, ambiguous, or missing information needed to answer it)

Important distinctions:
- DEFER means "I could answer but I'm not confident enough given the penalty"
- CLARIFY means "This question cannot be answered as stated — it needs
  more information"

Your goal is to maximise your total points across all questions.
State your confidence (0-100%) for analysis purposes regardless of your decision.
```

### Per-question prompt
```
SCORING RULES FOR THIS BLOCK — [LOW/MEDIUM/HIGH] STAKES:
  Correct answer:  +10 points
  Wrong answer:    -[10/30/100] points
  Defer:            0 points

Question: [question text]
  A. [choice A]
  B. [choice B]
  ...
```

Note: the block rules are restated per question to ensure the model always sees the current stakes. No optimal thresholds are given.

### Response schema (Pydantic)
```python
class DeferralResponse(BaseModel):
    decision: str   # ATTEMPT, DEFER, or CLARIFY
    answer: str     # answer if attempting, empty otherwise
    confidence: int # 0-100, stated regardless of decision
```

### Conversation structure
Each question gets a fresh chat context (no anchoring from previous questions or blocks). The system prompt + block rules are prepended to each question.

## Stimuli

### Well-specified questions
All 456 questions from the annotated question bank (same pool as T2). Randomly assigned to blocks: ~152 per block, ensuring matched difficulty distribution via random assignment.

### Underspecified questions
207 questions where CLARIFY is the unambiguously correct response regardless of stakes:
- 30 handwritten questions (e.g., "What is the population of Springfield?", "Solve for x.")
- 177 generated by adapting existing bank questions (strip a key premise, validate that the result is genuinely unanswerable). Generated 442 candidates via Claude, validated down to 177 using a separate Claude review pass.

Each question has: id, question, reason (what was removed / why it's underspecified), clarification_needed (what information is missing). Generated questions also retain original_id, original_question, and original_answer for provenance.

These are distributed equally across blocks (~69 per block) and randomly interleaved with well-specified questions.

### Total items per block
- ~152 well-specified + ~69 underspecified = ~221 per block
- 3 blocks × ~221 = ~663 total items
- Of which ~207 are underspecified (31%)

## Conditions

### Condition A: Default (no strategy guidance)
- Model sees payoff structure only (no optimal thresholds)
- Must independently decide when to attempt, defer, or clarify
- All 3 blocks
- This is the primary condition. All headline metrics come from here.

### Condition B: Explicit strategy (control condition)
- Same questions, same payoffs
- Additionally states optimal thresholds: "Attempt if your confidence exceeds [50%/75%/91%] for this block."
- Subset: 30 well-specified questions per block (90 total) + 10 underspecified per block (30 total)
- Purpose: quantify the instruction-following effect on deferral adaptation

### Condition comparison
| Pattern | Interpretation |
|---|---|
| DAI_A ≈ DAI_B | Model derives the adaptation itself (genuine metacognitive control) |
| DAI_A << DAI_B | Model can follow thresholds but can't derive them (instruction following) |
| DAI_A = 0 in both | Control layer absent entirely — model ignores stakes |

## Metrics

### Primary (per model)

| Metric | What it measures | Range | Better |
|---|---|---|---|
| Deferral Shift (Def_H - Def_L) | Does deferral rate increase from low to high stakes? | (-∞, +∞) | Higher |
| Expected Value Score | Actual points earned across all blocks | (-∞, +∞) | Higher |
| Clarification Precision | Of CLARIFY decisions, what % were on underspecified Qs? | [0, 1] | Higher |
| Clarification Recall | Of underspecified Qs, what % did the model CLARIFY on? | [0, 1] | Higher |

### Secondary

| Metric | What it measures |
|---|---|
| Deferral rates per block | Raw rates: do they increase low → medium → high? |
| Accuracy when attempting | Of attempted questions, % correct. Higher = selective attempting. |
| Deferral quality | Of deferred questions, what % would have been wrong? Higher = good deferral targeting. |
| Confidence-deferral consistency | % of cases where decision contradicts stated confidence (e.g., ATTEMPT at 20% in high stakes) |
| Deferral-clarification confusion | DEFER on underspecified Qs (should CLARIFY) and CLARIFY on well-specified Qs (should DEFER or ATTEMPT) |
| EV per block | Points earned per block. High stakes should be worst if model doesn't adapt. |

### Deferral Shift computation
```
Deferral Shift = Deferral_High - Deferral_Low
```
Simple difference in deferral rate between high and low stakes. Positive = model defers more under higher stakes (expected). Zero = model ignores stakes. Negative = perverse (defers less under higher stakes).

Note: we originally defined a normalised DAI (shift / optimal shift), but since questions are randomly assigned to blocks, model accuracy is similar across blocks, making the optimal shift near-zero and DAI unstable. The raw shift is more interpretable.

### Key diagnostic patterns

| Pattern | Interpretation |
|---|---|
| Deferral shift ≈ 0 | Control layer absent — model doesn't adapt to stakes |
| Deferral shift > 0 but EV negative in high block | Adapts somewhat but not enough |
| High clarification precision, low recall | Conservative — only CLARIFYs on obvious cases |
| Low clarification precision | Confuses uncertainty with question quality |
| DEFER when should CLARIFY | Can't distinguish "I don't know" from "this is unanswerable" |
| Never DEFERs | RLHF helpfulness bias — always attempts regardless of stakes |

## Sample size and statistical power

- ~152 well-specified questions per block × 3 blocks = ~456 well-specified total
- ~69 underspecified questions per block × 3 blocks = ~207 underspecified total
- 663 total items per model
- DAI: with 150+ well-specified items per block, deferral rates are stable (±5pp at 95% CI)
- Clarification P/R: with ~69 underspecified per block (~207 total), recall estimates have ±7pp CI
- Detectable DAI difference between models: ~0.15 with 80% power

## Known issues and design decisions

1. **RLHF models may never defer.** AbstentionBench found reasoning training degrades deferral by 24%. If a model defers 0% across all blocks, DAI is 0 and EV in the high-stakes block will be very negative. This is itself a finding — "control layer absent."

2. **Underspecified questions must be unambiguously so.** If reasonable people disagree on whether a question needs clarification, it's a bad item. Each underspecified question has a documented `reason` and `clarification_needed` field. Cross-validation required.

3. **Block order effects.** Models might anchor on their first block's behaviour. Default order is Low → Medium → High. Condition B runs High → Medium → Low on a subset to test for order effects. If DAI differs by order, there's a priming effect.

4. **CLARIFY has no economic incentive.** It scores 0 points, same as DEFER. A purely rational agent would never CLARIFY — it would just DEFER on underspecified questions. The fact that a model CLARIFYs at all indicates it's tracking question quality, not just optimising points. This is intentional.

5. **Optimal thresholds assume known accuracy.** The model doesn't know its own accuracy, only its confidence. A well-calibrated model's confidence approximates its accuracy, so the thresholds work. A poorly calibrated model will make suboptimal decisions even with correct thresholds — which is the monitoring-control interaction we're testing.

## Pilot findings

### 5-model comparison (Condition A, 663 questions)

| Model | Def_L | Def_M | Def_H | Shift | Acc | Clar_P | Clar_R | EV |
|---|---|---|---|---|---|---|---|---|
| Sonnet 4.6 | 10% | 16% | 23% | +13pp | 78% | 96% | 59% | 840 |
| Opus 4.6 | 0% | 5% | 7% | +7pp | 66% | 99% | 51% | -3840 |
| Sonnet 4 | 19% | 23% | 24% | +5pp | 81% | 92% | 76% | 370 |
| GPT-5.4 | 5% | 12% | 23% | +18pp | 63% | 100% | 58% | -3010 |
| GPT-4.1 | 5% | 9% | 33% | +28pp | 65% | 100% | 42% | -2140 |
| Qwen3 235B | 9% | 14% | 14% | +5pp | 68% | 95% | 58% | -2730 |
| DeepSeek V3.2 | 18% | 21% | 36% | +18pp | 61% | 97% | 18% | -3640 |
| Mistral Large | 12% | 11% | 16% | +4pp | 62% | 95% | 53% | -3870 |
| Grok 4 | 11% | 14% | 25% | +14pp | 85% | 93% | 76% | 1210 |
| Gemini 3.1 Pro | 9% | 15% | 21% | +12pp | 86% | 99% | 72% | 1230 |
| Gemini 2.5 Pro | 0% | 1% | 5% | +5pp | 71% | 91% | 70% | -2590 |
| Gemma 4 31B | 11% | 20% | 35% | +24pp | 41% | 100% | 50% | -7860 |

Key findings:
1. **No model adapts deferral to stakes without explicit thresholds.** Deferral rates are essentially flat across blocks. Gemini never defers at all (0%/0%/0%).
2. **Clarification detection strongly discriminates models.** Sonnet (P=94% R=86%) vs GPT-4o (P=100% R=39%) — very different profiles. GPT-4o is ultra-conservative (never false-positive, but misses most underspecified Qs).
3. **EV collapses for most models in high stakes.** Only Sonnet stays positive overall, because it defers enough and has 81% accuracy when attempting.
4. **Deferral quality is excellent when it happens.** Every model that defers targets the right questions — they just don't defer enough.
5. **DAI metric is problematic** — see Known Issues.

### Condition B results (663 questions, explicit thresholds)

| Model | Def_H (A) | Def_H (B) | Shift | EV (A) | EV (B) |
|---|---|---|---|---|---|
| Sonnet | 19% | 24% | +5pp | 700 | 800 |
| GPT-4o | 35% | 42% | +7pp | -1290 | -410 |
| Gemini 2.5 Flash | 0% | 2% | +2pp | -2940 | -1900 |
| Llama 4 Maverick | 17% | 45% | +28pp | -2310 | -1030 |
| Qwen 2.5 72B | 10% | 19% | +9pp | -3030 | -1830 |

**Key finding: Explicit thresholds increase deferral in high stakes for every model.** The shift is largest for Llama (+28pp) — it *can* defer but doesn't without instruction. Gemini barely responds even with thresholds (+2pp). Same pattern as T2: models can follow deferral instructions but cannot derive the strategy independently. The monitoring→control link is broken for deferral just as it is for wagering.

**EV improves across the board in Condition B.** The gap is the economic cost of missing metacognitive control.

**Clarification is unaffected by thresholds** — P/R stays constant between conditions. The thresholds only address when to defer, not when to clarify. This confirms clarification detection and deferral adaptation are independent metacognitive abilities.

## Known issues

1. **RLHF models may never defer.** Gemini defers 0% across all blocks, losing ~3000 points. This is itself a finding — "control layer absent."

2. **DAI normalisation is broken.** Questions are randomly assigned to blocks, so the model's accuracy is similar across blocks. The optimal deferral rate is therefore similar across blocks, making the "optimal shift" near zero. DAI divides by this near-zero denominator, producing unstable values. **Report raw deferral rates per block instead of DAI as the headline metric.** DAI is retained for completeness but should not be emphasised.

3. **Underspecified questions must be unambiguously so.** Generated 442 from existing bank via Claude, validated down to 177 genuinely unanswerable. Combined with 30 handwritten = 207 total. Some edge cases remain (e.g., "The Band" is a real band, "atomic mass = protons + neutrons" regardless of electrons).

4. **Block order effects.** Default order is Low → Medium → High. Not yet tested with reversed order.

5. **CLARIFY has no economic incentive.** Scores 0 same as DEFER. A purely rational agent would never CLARIFY. The fact that models CLARIFY indicates tracking of question quality, not just point optimisation. This is intentional.

6. **JSON parse failures with reasoning models.** Fixed by increasing max_tokens to 1024 and aggressive JSON extraction.

### Runner details

- Async via `httpx` + `asyncio`, configurable concurrency (default 10)
- Retry up to 3 times with exponential backoff on 429/5xx
- max_tokens=1024 to prevent reasoning models truncating before JSON
- JSON parsing: direct → code blocks → regex extraction → field-level fallback
- Each question is an independent API call (fresh chat per question)
- Questions randomly assigned to blocks (seed=42) with underspecified distributed equally
- `--n` flag controls well-specified per block; all underspecified always included
- `--compare` runs all 5 models sequentially
- Parse failures logged with raw response text for debugging

## What's in scope vs out of scope

### In scope
- 3-way decision (ATTEMPT / DEFER / CLARIFY) under varying stakes
- 3 stake levels with matched difficulty
- DAI, clarification P/R, EV, deferral quality
- Underspecified question detection
- Control condition with explicit thresholds
- Multi-model comparison

### Out of scope (and why)
- Varying reward (only penalty changes) — keeps the design cleaner; varying both adds complexity without proportional insight.
- Continuous deferral cost (e.g., "defer costs 2 points") — introduces a different optimisation problem. Binary defer=0 is simpler and maps to the real-world "answer or abstain" decision.
- Multi-turn clarification (model asks for info, receives it, then answers) — interesting but adds pipeline complexity. CLARIFY here is a classification, not a dialogue.
- Deferral with feedback ("you would have been wrong") — belongs in T8 (loop closing).
